## 1. 목적과 사용자 문제

Jena Web은 웹 검색과 이미지 탐색에 집중한 데스크톱 웹 탐색 앱이다. 사용자가 선택한 검색 사이트에서 검색하고, 결과 사이트를 앱의 탭으로 열어 탐색을 이어가도록 한다.

주 사용자는 검색 결과와 여러 참고 사이트를 오가며 자료를 찾는 사용자다. 검색 결과를 유지하면서 사이트를 열고, 자주 찾는 페이지를 북마크하며, 재방문 때 유효한 로그인 상태를 유지하는 것이 핵심 가치다. 개발 도구나 범용 브라우저의 모든 기능을 제공하는 것은 제품 목표에 포함하지 않는다.

## 2. 확정된 방향

| 항목 | 합의 내용 |
|---|---|
| 대상 플랫폼 | macOS 우선 개발, Windows 후속 지원 |
| 웹 엔진 | Blink 기반. 구체적인 임베딩 프레임워크는 미정 |
| 검색 서비스 | 사용자가 검색엔진 선택 |
| 웹 검색 | 선택한 검색 사이트의 결과 페이지를 앱 탭에서 표시 |
| 이미지 검색 | 검색 사이트의 이미지 검색 결과 페이지를 앱 탭에서 표시 |
| 결과 사이트 탐색 | 앱 내부의 현재 탭 또는 새 탭에서 표시 |
| 새 탭 설정 | 새 탭으로 열도록 설정한 경우 기존 결과 탭을 보존하고 앱 내부 새 탭 생성 |
| 북마크 | 제공 |
| 로그인 | 사이트가 허용하는 유효기간 내 로그인 상태 유지 |
| 비밀번호 자동입력 | 필요 없음 |
| 개인정보 설정 | 인터넷 사용 기록 삭제, 사이트 설정, 서드 파티 쿠키와 팝업 제어 |

검색 결과 데이터를 API로 가져와 자체 갤러리나 검색 목록을 만들지 않는다. Google을 선택해도 일반 Google 검색 페이지를 탐색하는 방식이므로 Google 검색 API 키나 검색 API 호출료가 필요하지 않다. 이 내용은 검색 API 비용에 관한 것으로, 앱 개발·배포 비용 전체가 없다는 뜻은 아니다.

원안에는 비밀번호 저장과 기기 키체인 저장이 포함되어 있다. 후속 대화에서 확인된 핵심 목적은 로그인 유지다. 로그인 유지 기능은 쿠키와 사이트 데이터 보존으로 정의하며, 별도 비밀번호 저장 기능의 포함 여부는 미확정으로 남긴다. 원안의 항목을 삭제한 것으로 해석하지 않는다.

## 3. 가정과 미확정 사항

- 앱의 일반 탐색 프로필을 지속적으로 사용하며, 앱을 종료했다 다시 실행해도 필요한 사이트 데이터를 보존하는 것을 로그인 유지 요구로 해석한다.
- Google은 선택 가능한 검색엔진 후보에 포함한다. 다른 제공처 목록과 최초 기본값은 미정이다.
- 웹 검색과 이미지 검색의 제공처를 별도로 선택할지, 하나의 기본 검색엔진을 공유할지는 미정이다.
- 현재 탭/새 탭 설정의 최초 기본값, 새 탭 생성 후 포커스 이동 여부는 미정이다.
- macOS 최소 버전, Apple Silicon·Intel 지원 범위와 Windows 지원 버전은 미정이다.
- 기술 스택, 배포 채널, 자동 업데이트 방식, 개발 일정은 아직 확정하지 않는다.
- 외부 검색 서비스와 사이트의 가용성 및 로그인 정책에 의존한다. 모든 사이트에서 동일한 로그인 유지 기간을 보장할 수 없다.

## 4. 사용자 흐름

### 4.1 웹 검색과 사이트 방문

1. 설정에서 사용할 검색엔진을 선택한다.
2. 앱 검색창에 검색어를 입력하고 웹 검색을 실행한다.
3. 선택한 검색엔진의 검색 결과 페이지가 앱 탭에 열린다.
4. 검색 결과 링크를 클릭한다.
5. 현재 탭 열기 정책이면 해당 탭에서 이동한다. 새 탭 열기 정책이면 결과 탭을 남겨 두고 앱 내부 새 탭에서 사이트를 연다.
6. 뒤로 가기나 탭 전환으로 결과 목록에 돌아가 탐색을 이어간다.

일반 HTTP/HTTPS 페이지 탐색은 앱 안에서 처리한다. 외부 앱 호출 링크와 파일 다운로드는 별도 정책이 필요한 항목이다.

### 4.2 이미지 검색

1. 검색창에서 이미지 검색을 선택하고 검색어를 입력한다.
2. 설정에 따른 검색 서비스의 이미지 검색 결과 페이지를 앱 탭에 표시한다.
3. 썸네일 선택과 미리보기는 해당 검색 사이트가 제공하는 화면과 동작을 따른다.
4. 원본 사이트로 이동하는 링크는 앱의 탭 열기 정책을 따른다.

이미지 썸네일 클릭을 모두 외부 페이지 이동으로 취급하지 않는다. 검색 페이지 내부의 미리보기는 유지한다. 이미지 업로드를 통한 역이미지 검색을 앱 고유 기능으로 제공하는 것은 아직 합의하지 않았다.

### 4.3 사이트별 로그인 유지

1. 사용자가 사이트의 로그인 화면에서 직접 로그인한다.
2. 앱이 사이트에서 발급한 쿠키와 필요한 사이트 데이터를 보존한다.
3. 같은 프로필에서 동일 사이트를 다른 탭으로 열거나 앱 재실행 후 방문하면 유효한 인증 상태를 재사용한다.
4. 사이트에서 로그아웃하거나 인증을 만료·취소하면 사이트의 재로그인 절차를 따른다.

앱이 로그인 유효기간을 임의로 연장하지 않는다. 사이트가 종료 시 만료를 요구하거나 재인증을 요구하는 경우 이를 따른다. 서로 다른 사이트의 인증 정보를 앱이 임의로 공유하지 않는다.

### 4.4 개인정보 관리

1. 사용자가 개인정보 설정에서 삭제할 데이터 종류와 범위를 선택한다.
2. 로그인 해제 등 예상 영향을 확인하고 삭제를 실행한다.
3. 삭제 완료 또는 실패 항목을 확인한다.
4. 사이트별 설정에서 권한·쿠키·팝업 정책을 확인하거나 변경한다.

## 5. 기능 요구사항과 수용 기준

아래 세부 동작은 합의한 방향을 구현·검증하기 위한 기획 기준이다. 미확정 기본값은 임의로 확정하지 않는다.

| ID | 요구사항 | 수용 기준과 목적 |
|---|---|---|
| F01 | 검색엔진 선택 | 지원 목록에서 선택한 제공처로 검색하고 앱 재실행 후 선택을 유지하여 반복 설정을 줄인다. |
| F02 | 웹 검색 | 한글·공백·특수문자가 포함된 검색어를 훼손하지 않고 해당 서비스의 결과 페이지로 전달한다. 빈 입력은 검색하지 않는다. |
| F03 | 이미지 검색 | 검색어를 이미지 검색 결과 페이지로 전달한다. 결과 데이터 수집용 검색 API를 호출하지 않는다. 미지원 제공처는 이유를 알리고 선택을 유도한다. |
| F04 | 주소 직접 이동 | 유효한 HTTP/HTTPS 주소를 입력하면 검색 결과를 거치지 않고 해당 사이트로 이동한다. 상세 주소 판별 규칙은 구현 시 정의한다. |
| F05 | 탭 탐색 | 탭 생성·전환·닫기를 제공한다. 새 탭 열기 설정 시 결과 페이지를 보존하고 대상 사이트를 앱 탭에 표시한다. 중복 탭 생성과 외부 브라우저의 의도치 않은 실행이 없어야 한다. |
| F06 | 기본 이동 | 뒤로·앞으로·새로고침과 현재 주소 표시를 제공하여 탐색 위치와 실제 접속 사이트를 확인할 수 있다. |
| F07 | 북마크 | 페이지 제목·주소를 저장하고 목록에서 다시 연다. 편집·삭제 기능을 제공하며 앱 재실행 후에도 저장 상태를 유지한다. |
| F08 | 로그인 유지 | 영속 로그인을 허용하는 테스트 사이트에서 다른 탭 및 앱 재실행 후 인증 상태를 유지한다. 만료·로그아웃 후에는 재인증을 요구한다. |
| F09 | 기록 삭제 | 방문 기록, 쿠키·사이트 데이터, 캐시를 구분한다. 방문 기록만 삭제했을 때 로그인 데이터까지 삭제하지 않는다. 실제 제공할 기간·사이트 범위는 상세 설계에서 확정한다. |
| F10 | 사이트 데이터 삭제 | 특정 사이트 데이터 삭제 시 대상 범위를 표시하고 다른 사이트에 영향을 주지 않는지 검증한다. 하위 도메인·연동 로그인 영향도 확인한다. |
| F11 | 사이트 권한 | 사이트별 허용·차단 상태를 확인·변경할 수 있다. 위치·카메라·마이크·알림 등 구체적인 지원 권한 목록은 엔진 검증 후 확정한다. |
| F12 | 서드 파티 쿠키 | 정책을 선택하고 실제 적용 여부를 검증한다. 차단으로 로그인·콘텐츠가 동작하지 않는 경우 설정 변경 경로를 제공한다. |
| F13 | 팝업 제어 | 허용·차단과 사이트별 정책을 제공한다. 사용자가 명시적으로 새 탭을 여는 행동과 자동 팝업을 구분한다. |

폼 제출, 페이지 내부 이동, 스크립트로 여는 창, 인증용 팝업은 일반 결과 링크와 구분해 검증한다. 모든 클릭을 강제로 새 탭으로 보내는 방식으로 로그인이나 이미지 미리보기를 깨뜨리지 않아야 한다.

## 6. 화면 구성과 상태

시각 디자인과 상세 배치는 후속 단계에서 결정한다.

| 화면 | 진입과 주요 내용 | 완료·다음 행동 |
|---|---|---|
| 탐색 화면 | 앱 실행 또는 탭 선택. 탭 목록, 주소·검색 입력, 웹/이미지 선택, 이동 버튼, 웹 콘텐츠 | 검색·사이트 이동·탭 전환 |
| 북마크 화면 | 북마크 메뉴. 저장된 제목·주소와 관리 기능 | 저장 페이지 열기 또는 편집 |
| 일반 설정 | 설정 메뉴. 검색엔진 및 탭 열기 정책 | 설정 적용 후 탐색으로 복귀 |
| 개인정보 설정 | 설정 메뉴. 삭제할 데이터 종류·범위와 영향 설명 | 확인 후 삭제, 결과 표시 |
| 사이트 설정 | 현재 사이트 또는 설정 목록. 권한·쿠키·팝업 상태 | 정책 변경 후 필요 시 페이지 새로고침 |

공통 상태 정의:

- 기본: 현재 주소·검색엔진·선택 상태를 확인할 수 있다.
- 로딩: 해당 탭의 로딩 상태를 표시하고 다른 탭은 계속 사용할 수 있다.
- 비어 있음: 새 탭은 입력 경로를, 북마크가 없으면 추가 방법을 안내한다. 검색 결과 없음은 검색 사이트의 화면을 그대로 표시한다.
- 오류: 접속 또는 저장 실패 이유와 재시도 경로를 표시하고 입력값을 보존한다.
- 오프라인: 네트워크 연결 문제를 알리고 연결 복구 후 재시도할 수 있다. 로컬 북마크와 설정은 접근 가능해야 한다.
- 권한 거부: 차단된 권한과 사이트 설정으로 이동하는 경로를 제공한다. OS 권한 거부도 구분한다.
- 부분 성공: 여러 데이터 삭제 중 일부가 실패하면 성공·실패 항목을 구분하고 실패 항목을 다시 시도할 수 있다.

## 7. 데이터와 비기능 요구사항

| 데이터 | 보존 목적 | 관리 원칙 |
|---|---|---|
| 설정 | 검색엔진과 탐색 정책 유지 | 로컬에 보존 |
| 북마크 | 저장한 페이지 재방문 | 제목·주소 등 필요한 정보만 저장 |
| 방문 기록 | 방문 내역 관리 | 사용자 삭제 기능과 연결 |
| 쿠키·사이트 저장소 | 로그인과 사이트 기능 유지 | 엔진의 사이트 경계와 보안 정책 준수 |
| 캐시 | 반복 탐색 성능 | 로그인 데이터와 구분해 삭제 |
| 비밀번호 | 별도 저장 요구 미확정 | 로그인 유지 목적으로 직접 수집·저장하지 않음 |

- 외부 페이지에서 앱의 파일·시스템 기능에 임의로 접근할 수 없도록 엔진의 격리·보안 기능을 유지한다.
- 인증서 오류를 숨기거나 자동으로 우회하지 않는다.
- 검색어, 방문 URL, 쿠키, 인증 토큰, 비밀번호를 원격 분석에 전송하는 기능은 현재 범위에 없다.
- 키보드로 검색·탭 이동·북마크·설정 조작이 가능해야 하며 포커스와 접근 가능한 이름을 제공한다.
- 엔진 보안 업데이트를 반영할 수 있어야 한다. 배포·업데이트 운영 방식은 구현 전 결정한다.
- 성능 목표 수치는 대상 기기와 엔진 선정 후 정한다. 초기 실행 시간, 탭 전환 지연, 다중 탭 메모리를 측정하며 외부 사이트 응답 시간과 앱 자체 지연을 구분한다.
- macOS에서 구현한 검색·탭·로그인 정책은 Windows에서도 동일한 사용자 결과를 제공해야 한다.

## 8. 검증 지표와 출시 기준

신규 서비스의 이용률·수익 지표는 근거 없이 설정하지 않는다. 초기 버전은 실제 탐색 과업의 완료 여부로 검증한다. 다음 수치는 출시 검증 목표이며 측정된 실적이 아니다.

| 지표 | 초기 검증 목표 |
|---|---|
| 검색 → 결과 → 사이트 방문 과업 | 지원 검색엔진별 웹·이미지 시나리오 통과율 100% |
| 새 탭 열기 정책 | 합의한 링크 유형 테스트에서 원본 결과 탭 보존율 100% |
| 의도치 않은 외부 브라우저 실행 | 일반 HTTP/HTTPS 탐색 테스트에서 0건 |
| 로그인 재방문 | 영속 로그인을 허용하는 검증 사이트에서 유효 세션 재사용 시나리오 100% 통과 |
| 로그아웃·만료·삭제 | 인증 무효화 후 인증 상태가 잘못 복구되는 사례 0건 |
| 개인정보 삭제 범위 | 선택 대상 삭제 및 비선택 대상 보존 테스트 100% 통과 |
| 설정·북마크 유지 | 정상 종료 후 재실행 테스트 100% 통과 |

검증 결과는 개발·QA 기록에 남긴다. 검색 실행, 결과 탐색, 새 탭 생성, 저장 성공·실패, 데이터 삭제 성공·실패를 로컬 테스트에서 관찰하되 민감한 값은 기록하지 않는다. 이 지표를 위해 원격 사용자 추적을 도입하지 않는다.

출시 전에는 실제 제공처별 검색 경로, 한글 입력, 사이트 로그인, 로그인 팝업, 쿠키 차단, 오프라인, 인증서 오류와 삭제 실패를 확인한다. 통과율은 검증 범위에 대한 값이며 전체 웹사이트 호환성을 의미하지 않는다.

## 9. 진행 순서와 후속 결정

1. **macOS 기술 검증:** Blink 임베딩 후보를 비교하고 실제 검색 페이지, 탭 이동, 세션 저장, 개인정보 제어를 검증한다.
2. **macOS 핵심 탐색:** 검색엔진 선택, 웹·이미지 검색, 주소 이동, 기본 탐색, 탭, 북마크를 구현한다.
3. **macOS 로그인·설정 검증:** 로그인 유지와 만료, 삭제 범위, 사이트 권한, 쿠키·팝업 정책을 완성하고 출시 기준을 확인한다.
4. **Windows 확장:** 동일한 사용자 흐름을 이식하고 OS별 저장·권한·배포 동작을 검증한다.

위 순서는 작업 제안이며 일정이나 기능 축소를 확정하는 내용이 아니다. macOS 배포 범위는 기본 탐색뿐 아니라 합의한 로그인 유지와 개인정보 설정을 포함한다.

후속 결정 항목:

- 지원 검색엔진 목록과 기본값, 웹·이미지 제공처 설정 관계
- 탭 열기 기본값, 포커스 정책, 마지막 탭 닫기와 재실행 시 탭 복원
- 별도 비밀번호 저장 기능의 필요 여부
- 다운로드·외부 앱 링크·인증 팝업의 처리 범위
- 지원 OS·CPU 범위, 엔진 및 UI 프레임워크, 배포·업데이트 방식

## 10. 현재 범위에 포함하지 않는 기능

- 검색 결과 API를 통한 자체 결과 목록·이미지 갤러리
- 비밀번호 자동입력
- 앱 고유의 역이미지 검색 도구
- 개발자 도구 중심 기능
- 확장 프로그램 생태계, 기기 간 동기화, 모바일 버전

새로운 기능을 추가하거나 원안의 미확정 항목을 제외하려면 별도로 범위를 결정한다.
