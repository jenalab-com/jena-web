# 탭 추가 시 창 폭 증가 수정

- 원인: 탭 문서 너비와 스크롤 뷰 너비를 연결한 Auto Layout 제약이 창의 크기 계산에 전파됐다.
- 변경: BrowserTabListView가 주어진 가용 폭 안에서 스크롤 영역과 추가 버튼을 배치한다. 탭 문서의 frame은 fittingSize로 계산하며 문서 너비를 창 제약에 연결하지 않는다.
- 동작: 탭이 적으면 추가 버튼이 마지막 탭 옆에 위치하고, 넘치면 가용 폭 오른쪽에 고정된다. 탭을 닫을 때 스크롤 위치가 문서 범위를 벗어나지 않도록 보정한다.
- 보존: docs/backups/before-tab-scroll-width-*에 원본을 백업했다.
- 검증: 제품 컨트롤 클래스로 만든 AppKit NSWindow에 탭을 1개부터 100개까지 추가하며 창 폭 800pt 유지와 추가 버튼의 가시 범위를 assert로 확인했다. 100개에서 문서 폭 18396pt, 뷰포트 760pt, 추가 버튼 x=768/width=32였다. 실제 clipView의 가로 스크롤 이동도 확인했다.
- 한계: 제품 전체 창의 수동 시각 검증은 수행하지 않았다.
- 제품 빌드: `make build` 성공 (`BUILD SUCCEEDED`).
