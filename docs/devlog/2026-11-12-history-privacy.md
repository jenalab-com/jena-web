# 방문 기록과 개인정보 관리 제품 연결

- 목적: 채택 검증을 반복하지 않고 일상 탐색에 필요한 기록·삭제 UI를 구현한다.
- 변경: 성공한 HTTP/HTTPS 주 문서 로드를 SQLite visit에 저장하고 최근 500건 목록·새 탭 열기를 연결했다. 방문 기록 메뉴(⌘Y)와 개인정보 관리 창을 추가했다.
- 삭제: 기간별 앱 방문 기록, 명시한 사이트의 쿠키·저장 데이터, 전체 HTTP 캐시를 독립 선택한다. 확인 대화상자 후 실행하며 항목별 완료·부분 실패를 표시한다. 실제 데이터 삭제는 이번 개발 작업에서 실행하지 않았다.
- 경계: 쿠키는 지정 도메인 및 하위 도메인, 저장소는 정확한 origin의 localStorage·IndexedDB·Cache Storage·Service Worker다. 상위 도메인을 임의 추정하지 않는다. opaque partition은 변경 전에 거절한다.
- 선택: 웹 데이터 삭제에는 빈 탭만 남아 있어야 한다. 자동 탭 종료를 하지 않고 삭제 중 새 탐색·팝업·종료를 차단한다. 사용성이 제한되지만 열려 있는 문서의 즉시 재저장을 피한다. 서비스 워커 등의 완전한 재생성 차단을 보장하는 프로필 삭제는 아니다.
- 저장: v1 DB를 SQLite backup으로 보존한 뒤 v2로 테이블을 추가한다. 큐·세대 번호로 삭제 전에 대기 중이던 기록이 뒤늦게 재삽입되는 것을 막는다.
- 한계: SPA 내부 이동 기록, 모든 종류의 사이트 데이터 삭제, 엔진 응답 지연 시 강제 중단 UI는 이번 범위에 없다. 페이지 로드 시점의 제목을 저장한다.
- 확인: macOS Debug 컴파일·패키징. 테스트 실행, 앱 자동 실행, 수동 검증 요청 없음. Xcode의 기존 iOS Simulator 버전 경고는 macOS 빌드와 별개이며 환경을 변경하지 않았다.
