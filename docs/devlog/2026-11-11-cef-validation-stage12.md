# CEF 검증 12차: 네이티브 뷰 기초 측정과 채택 판단

## 최종 판단

**Swift/AppKit + CEF의 기술적 연결 가능성은 확인했지만, 제품 엔진으로 CEF를 확정 채택하는 것은 보류한다.** Swift·macOS 네이티브 방향을 바꾸거나 Electron·React·WebKit으로 전환한 결정은 아니다. 현재 후보 코드와 요구사항을 유지한다.

12차까지의 결과는 “일단 모두 구현 가능한 것으로 보고 제품 개발”을 승인할 근거가 부족하다. 특히 10차 탐색 의도 오분류, 11차 권한 요청·조회 불일치, 사이트 데이터 삭제 경계가 남아 있다. 검증 차수의 증가나 assertion 통과 개수로 이 조건을 대체하지 않는다.

## 이번 구현과 시험

- [Stage12Probe.mm](../../validation/cef-spike/Stage12Probe.mm): 11차 보안 probe를 복사해 native NSView 크기 변경, 표시·숨김, 포커스, 객체 식별 조회용 명령을 추가했다.
- [ui-stage12.py](../../validation/cef-spike/ui-stage12.py): 두 CEF browser 각각 24회 크기를 변경한다. 초기 browser ID·NSView 주소, 문서 marker와 입력값이 유지되는지 검사한다.
- native focus 요청 후 document.hasFocus, CDP 한글 문자열 삽입, 웹 접근성 트리의 이름 있는 textbox, 스크롤 반응을 검사한다.
- requestAnimationFrame 간격과 시험 프로세스 및 하위 프로세스의 RSS를 관측한다. 외부 사이트 대신 로컬 HTML fixture를 사용한다.
- 별도 build/stage12-probe 앱과 실행별 profile·mailbox·로그를 생성한다. 기존 1~11차 소스와 산출물을 보존한다.

시험 기기는 macOS 26.6.2 (25G83), arm64다. Swift 6 모드, CEF 156.0.27, sandbox helper를 사용한다. 제품 지원 OS·기준 기기 목록을 확정하는 의미는 아니다.

## 측정 해석

실행별 결과와 프레임·RSS 값은 [stage12-summary.json](../../validation/cef-spike/evidence/stage12-summary.json)에 기록한다.

| 실행 | 기능 확인 | 종료 | 네트워크 서비스 재시작 | RSS 합계 전 → 후 |
|---|---:|---:|---:|---:|
| [초기](../../validation/cef-spike/evidence/ui-stage12-20261111-143449/results.json) | 20/22 | 0 | 0 | 567.66 → 565.27 MiB |
| [앱 활성화 보완 후](../../validation/cef-spike/evidence/ui-stage12-20261111-143709/results.json) | 22/22 | 0 | 0 | 561.31 → 583.47 MiB |

초기에는 두 창에서 native focus 요청 후 document.hasFocus가 false였다. Probe.focus에서 NSApplication 활성화 후 창·CEF 포커스를 요청하도록 수정했고 재시험에서는 두 창 모두 true였다. 초기 소스·번들은 보존하고 stage12-active-probe를 별도로 만들었다. 이 수정은 검증용 명령에 한정하며 제품의 탭 전환마다 앱 활성화를 강제하는 정책을 정한 것이 아니다.

두 실행 모두 CefShutdown 반환을 확인했다. 짧은 두 실행이며 장시간 안정성이나 누수 검증으로 집계하지 않는다.

보완 실행의 rAF 간격 중앙값은 두 browser 모두 약 16.7ms였다. slot 0은 p95 약 127.3ms, 최대 약 1,182.7ms였고 slot 1은 p95 약 17.7ms, 최대 약 41.6ms였다. 측정 구간에 크기 변경뿐 아니라 숨김·표시·포커스 전환도 포함되므로 긴 간격의 원인을 분리하지 못했다. **중앙값만으로 UI가 부드럽다고 판정하지 않는다.**

- 프레임 간격은 웹 페이지의 requestAnimationFrame callback 간격이다. AppKit 표시 지연·화면에 실제 제시된 프레임·키 입력 지연 전체가 아니다. mailbox 왕복, 프로그램 방식의 크기 변경과 다른 창의 스케줄링도 영향을 준다.
- RSS 합계는 공유 메모리를 중복 포함할 수 있으며 macOS physical footprint가 아니다. 전후 두 표본만으로 메모리 누수나 장시간 안정성을 판정하지 않는다.
- PRD D09의 성능 예산이 미정이므로 수치가 낮거나 높다는 이유만으로 성능 게이트를 통과 또는 실패 처리하지 않는다.
- CDP Input.insertText의 한글 성공은 실제 macOS IME 조합·후보창·조합 중 취소 검증이 아니다.
- 웹 접근성 트리의 textbox 관측은 VoiceOver·네이티브 접근성 계층 전체 검증이 아니다.
- 두 AppKit 창은 browser 인스턴스 시험용이다. 실제 탭 바, 드래그, SwiftUI 갱신, 설정 UI 겹침·클릭 가로채기는 구현하지 않았다.

## 다음 작업의 우선순위

연속 번호의 탐색적 검증을 무기한 늘리기보다, 아래 차단 문제를 해결하고 해당 게이트를 재검증하는 작업으로 전환한다. 이는 후속 제안이며 이번 요청에서 추가 기능 개발이나 스택 교체를 실행한 것은 아니다.

1. **탐색 분류 보완:** 10차 JavaScript 이동 반례를 실패 테스트로 유지하고 일반 링크 정책 경로를 고친다. 해결하지 못하면 새 탭 요구를 충족하지 못한 것으로 보고한다.
2. **권한 경로 확정:** 위치 요청 문제를 조사하고 지속 정책·query·OS 상태를 일치시킨다. 권한을 요구에서 임의로 제외하지 않는다.
3. **삭제·쿠키 정책 확정:** 사이트 삭제의 하위 도메인·공유 쿠키 범위와 CHIPS·사이트 예외를 정의하고 구현 가능성을 입증한다.
4. **제품 수준 수용 시험:** 사용자의 직접 Google·네이버 인증, 실제 IME·VoiceOver·탭 UI, 합의된 성능 예산과 장시간 측정을 수행한다.

기술적으로 불가능한 차단 문제가 확인되면 Blink 임베딩 대안을 비교한다. 현재 자료만으로 엔진 변경이나 OS 공통화를 결정하지 않는다. 배포 서명·공증·업데이트와 제품 전체 QA도 별도 잔여 작업이다.

## 재현

```sh
python3 validation/cef-spike/build-stage12-probe.py
validation/cef-spike/.venv/bin/python validation/cef-spike/ui-stage12.py
```

각 실행은 시험 browser만 정상 종료한다. 기존 프로필 삭제나 다른 서비스 종료를 수행하지 않는다. 설계 문서 상태 갱신 전 원본은 docs/backups에 보존한다.
