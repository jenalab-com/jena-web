# 비동기 로그인 팝업 허용 경로

- 증상: 사용자가 Pinterest의 Google 로그인 버튼이 무반응이라고 보고했다. 계정 로그인이나 재현 실행은 하지 않았다.
- 확인한 코드 문제: OnBeforePopup이 user_gesture=false이면 사용자 설정 확인 없이 무조건 차단하고 안내도 표시하지 않았다. 이것이 실제 Pinterest 증상의 원인인지는 미확정이다.
- 변경: 기존 사이트 설정에 팝업 허용/차단/기본값 복원을 추가했다. 비동기 팝업은 최상위 opener 사이트의 CEF POPUPS 적용값이 ALLOW인 경우 허용한다. 사용자가 클릭한 팝업은 기존 경로를 유지한다. 차단 시 상태 메시지로 설정 경로를 안내한다.
- 문맥: 엔진이 만든 popup browser를 기존 호스트 탭으로 수용해 POST·opener를 보존하는 경로를 유지한다. URL을 추출해 새 GET으로 재시도하거나 OAuth 목적지를 하드코딩하지 않는다.
- 제한: Chromium 단계에서 callback 이전에 차단된 요청은 앱 상태 안내를 거치지 않을 수 있다. 설정을 허용한 뒤 사용자가 원래 버튼을 다시 눌러야 한다. Google 로그인 성공이나 쿠키 호환성을 확인했다고 주장하지 않는다.
- 확인 범위: Debug 컴파일·패키징만 수행. 앱·프로세스 종료, 자동 실행, 추가 수동 검증 요청 없음.
