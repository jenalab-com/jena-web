## 1. 엔진 채택을 위한 검증

기존 사용자 프로필을 사용하지 않고 별도 테스트 프로필과 테스트 계정을 사용한다. 버전·OS·CPU·재현 단계·실제 결과를 기록한다. 테스트 종료를 프로필 임의 삭제 승인으로 해석하지 않는다.

| ID | 실험 | 통과 조건 | 실패 시 조치 |
|---|---|---|---|
| G01 | 네이티브 앱 UI와 외부 웹 프로세스 분리, 외부 frame의 네이티브 명령 접근·엔진 메시지 위조 | 비신뢰 콘텐츠가 앱 명령·파일에 접근하지 못함 | 경계 수정 후 재검증 |
| G02 | 일반 링크, target blank, 앵커, 이미지 미리보기, GET/POST 폼, 리디렉션, window.open | 새 탭 정책 준수, 원본 보존, 중복 없음, 폼·미리보기 유지 | 탐색 의도 검출 경로 변경; 불가능하면 후보 재평가 |
| G03 | 영속 쿠키·세션 쿠키·로컬 저장소, 재실행, 로그아웃·서버 취소 | 유효 상태 재사용, 만료·취소 상태 복원 없음 | 프로필 정책 재검토 |
| G04 | 두 사이트·하위 도메인·분할 저장소·IndexedDB·service worker fixture에 선택 삭제 | 실제 선택 대상 삭제, 무관한 데이터 보존, 재생성 식별 | 공개 API 한계 기록; 전체 삭제로 우회하지 않고 후보 비교 |
| G05 | first/third party, iframe, JS 쿠키, Set-Cookie, 분할 쿠키, 사이트 예외 | 허용·차단 정책이 요청·읽기·저장에 일관되게 적용 | CEF 채택 보류, Blink 통합 대안 검토 |
| G06 | 위치·카메라·마이크·알림 후보, OS 거부, 임베디드 origin | 요청·조회 일치, 사이트 경계 유지, 거부 복구 안내 | 지원 권한·적용 방식을 결정 목록에 보고 |
| G07 | 실제 검색 제공처, 직접 로그인·OAuth 팝업·opener 복귀 | 앱 내부 탐색과 인증 흐름 정상, 제공처 제한 식별 | 불가 사이트 명시; 요구 충돌이면 확인 |
| G08 | AppKit/SwiftUI 겹침·IME·responder·키보드·보조 기술, 탭 드래그·스크롤·창 리사이즈, 다중 탭, 정상 종료 | 페이지가 UI 클릭을 가로채지 않음, 상태 보존, 자원 측정 | 뷰 배치·생명주기 수정 |
| G09 | Swift/Objective-C++/CEF 초기화·메시지 루프·helper, 탭 종료 중 callback, SwiftUI 갱신 | 웹 호스트 재생성 없음, 해제 후 callback 접근 없음, sandbox 유지, 입력·프레임 시간 측정 | wrapper·생명주기 수정, 통합 불가 시 채택 보류 |

G04·G05·G09는 우선 시행한다. 하나라도 공개 API로 요구를 충족하지 못하면 CEF 채택을 확정하지 않는다. 현재 문서는 해당 기능 구현이 가능하다는 실증 결과가 아니다.

## 4. 남은 검증과 종료 기준 — 8차 이후

차수는 실행 기록 단위이며 통과 기준이 아니다. 12차를 CEF 채택 판단을 정리하는 목표로 두되, 미검증·실패 항목이 있으면 조건부 또는 보류로 판정한다. 완료를 위해 요구를 임의로 삭제하거나 완화하지 않는다. 아래는 다음 작업의 묶음이며 각 차수에 모든 항목이 반드시 끝난다는 일정 보장은 아니다.

| 목표 차수 | 검증 묶음 | 연결 게이트 | 주요 잔여 항목 |
|---|---|---|---|
| 9차 | 개인정보·로그인 유지 | G03·G04·G05·G07 | 만료·로그아웃·서버 취소, 저장소 인증, 선택 삭제 경계·재생성, 분할 쿠키·사이트 예외, 실제 인증 제공처 제한 |
| 10차 | 탐색·검색·새 탭 | G02·G07 | 검색 결과·이미지 미리보기, 링크·폼·팝업·opener·리디렉션, OAuth 복귀 |
| 11차 | 권한·보안 경계 | G01·G06 | 외부 콘텐츠의 네이티브 접근 차단, origin별 권한, OS 거부·복구 |
| 12차 | 네이티브 UI·안정성과 채택 판단 | G08·G09 | IME·포커스·접근성·스크롤, 다중 탭·리사이즈, callback 소유권·slot 세대, 장시간 자원·프레임 측정 |

각 묶음이 끝나면 통과·실패·미검증과 재현 근거를 게이트별로 정리한다. 실제 계정 인증, 제품 정책 선택, 성능 기준처럼 사용자 입력이 필요한 항목은 필요한 시점에 구체적으로 확인한다. 테스트 fixture의 영속 쿠키만으로 실제 사이트 로그인 유지를 통과 처리하지 않는다.

엔진 검증 종료는 G01~G09의 필수 조건에 근거가 있고 미해결 채택 차단 사유가 없는 시점이다. 12차에 미해결 사항이 있으면 추가 검증 목록과 채택 보류 이유를 제시한다. 배포 서명·공증·업데이트와 제품 전체 QA는 이 엔진 채택 판단과 별도다.


### 9차 이후 잔여 판정

- G03: 로컬 서버에서 영속·세션 쿠키와 LocalStorage 인증, 재실행, 만료·로그아웃·서버 취소를 확인했다. 실제 사이트 인증·서버별 정책은 미검증이다.
- G04: A origin 삭제는 B를 보존했지만 sub.a.test 인증과 Domain=a.test 공유 쿠키도 보존했다. 사이트 전체 삭제를 의미하지 않는다. 하위 도메인·분할 저장소·기간 삭제 범위는 미해결이다.
- G05: HttpOnly 서드 파티 인증 차단과 CHIPS의 최상위 사이트별 격리를 확인했다. 현재 제한에서 분할 쿠키는 허용된다. 사이트 예외 및 제품 정책과의 일치는 미확정이다.
- G07: 사용자 지정 우선 대상은 Google·네이버다. 두 초기 로그인 화면의 접근만 확인했으며 실제 인증·유지·OAuth 성공을 뜻하지 않는다.


### 10차 이후 잔여 판정

- G02: OnBeforeBrowse의 user gesture·GET·TT_LINK 조건만으로 일반 링크를 분류하는 후보는 JavaScript 이동 반례에서 실패했다. 후보 채택을 보류하고 의도 검출을 보완해야 한다. 폼·popup POST·opener 보존의 17개 통과를 전체 탐색 통과로 확대하지 않는다.
- G07: Google·네이버 웹·이미지 결과 콘텐츠 접근을 관측했지만 Google 웹은 25초 내 문서 complete 상태가 아니었다. 실제 결과 클릭·미리보기·계정 인증·OAuth는 남아 있다.
- G05·G09: 새 browser/popup 첫 탐색과 쿠키 정책 적용의 순서는 이번 새 창 adapter에서 미검증이다.


### 11차 이후 잔여 판정

- G01: 웹 진입점 부재, postMessage 정책 위조 실패, 로컬 파일 fetch 차단, cross-origin DOM 격리, 두 위험 스킴 이동 거절을 확인했다. probe의 웹 제목 기반 종료 장치를 별도 보안 앱에서 제거했다. 제품 브리지·전체 메시지 경계 검증 완료는 아니다.
- G06: 알림 요청·query 거부와 A/B origin 분리는 확인했다. 위치 요청은 응답 부재·query prompt로 실패했다. 카메라·마이크 요청은 거부됐지만 query는 prompt여서 저장 정책과 조회 일치는 미확인이다. 허용·OS 거부·철회·복구 안내는 미검증이다.
- 12차 판단에는 기존 G02와 이번 G06 보류를 함께 포함한다. UI 검증 성공만으로 이 보류 항목을 통과 처리하지 않는다.


## 5. 12차 종합 판단

CEF의 제품 엔진 확정 채택을 **보류**한다. Swift/AppKit 네이티브 방향은 유지하고 다른 스택으로 자동 전환하지 않는다. 전체 게이트를 통과한 것으로 기록하지 않는다. 게이트별 근거와 잔여 사항은 [12차 종합표](devlog/2026-11-11-cef-validation-stage12.md)를 기준으로 한다.

12차는 두 native 창 각각 24회 리사이즈, browser·NSView·문서 유지, 표시 전환, 웹 접근성 트리, 스크롤과 프레임·RSS 관측을 수행했다. 초기 포커스 실패는 앱 활성화 보완 후 재시험에서 통과했다. 실제 IME·VoiceOver·탭 UI·장시간 안정성과 미정 성능 예산을 대신하지 않는다.

후속 우선순위는 G02 탐색 의도 분류 수정, G06 권한 경로 수정, G04·G05 삭제·쿠키 정책 범위 확정, 실제 제공처·네이티브 UX 수용 시험이다. 탐색적 검증 차수를 무기한 추가하는 대신 차단 문제별 수정·재검증으로 진행하는 것을 제안한다. PRD 요구를 축소하거나 엔진 교체를 실행한 결정은 아니다.


## 6. 탐색 분류 수정 후 상태

10차의 user gesture·GET·TT_LINK 기반 URL 재생성 후보를 별도 수정 probe에서 제거했다. 격리 world에서 최상위 문서의 trusted 일반 링크 기본 동작만 새 창 대상으로 바꾸고 엔진이 생성한 browser를 native 호스트에 수용한다.

기본 회귀 17개, 기존 JavaScript 버튼 반례 2개, 경계 회귀 10개가 통과했다. G02의 기존 반례는 해결됐으며 이전 절의 실패 기록은 당시 이력이다. 전체 G02 통과는 아니다. iframe 링크·페이지 이벤트 전파·수정키·키보드·실제 제공처 클릭·미리보기와 popup 초기 정책 경합은 남아 있다. G06·G04 및 CEF 확정 채택 보류는 유지한다.


## 7. G02 전체 수용 검증 후 확정

사용자가 확인한 전체 검증 범위는 G02다. 기존 로컬 29개에 iframe·이벤트 전파·키보드·수정키·named target·리디렉션 등을 포함한 로컬 60개, 실제 Google·네이버 8개를 실행해 총 68/68이 통과했다. 두 제공처의 이미지 확대 미리보기는 클릭 전후 캡처도 확인했다.

**G02: 정의한 수용 매트릭스 통과, 탐색 분류와 관리 browser 생성 방식 확정.** 기준은 [NavigationFullProbe.mm](../validation/cef-spike/NavigationFullProbe.mm)와 [격리 링크 정책](../validation/cef-spike/navigation-full/link-policy.js)이며, [확정 기록](devlog/2026-11-11-navigation-acceptance.md)에 항목별 근거가 있다. 앞 절의 G02 보류·부분 검증은 당시 이력이다.

이 결정은 모든 웹사이트의 미래 변경이나 제품 UI 완성을 보장하지 않는다. G04 삭제, G05 쿠키 정책 전체, G06 권한, G07 실제 계정 인증·OAuth, G08·G09 제품 UX·안정성은 별도이며 CEF 전체 채택 보류는 해제하지 않는다. 실제 사이트와 CEF 버전 변경 시 G02 회귀 매트릭스를 다시 실행한다.


## 8. 권한·선택 삭제 소스 수정 후 검증

[수정·검증 기록](devlog/2026-11-11-permission-privacy-fix.md): 별도 네이티브 probe에서 권한·삭제 54개와 보안 회귀 25개, 총 **79/79 통과**. 이전 9차·11차의 실패와 관측은 당시 이력으로 보존한다. G02 확정 소스는 변경하지 않았다.

- **G06 부분 해결:** 위치·카메라·마이크·알림의 명시적 거절, 실제 웹 권한 조회 일치, 재실행 유지, 초기화 후 prompt를 확인했다. 미디어 요청 callback도 거절을 엔진 설정에 저장한다. 위치는 기존 설정과 approximate/precise 구조 설정을 함께 반영했다. 명시적 차단을 설정하지 않은 위치 prompt callback 문제, OS 허용·거부·복구, 임의의 요청 origin/최상위 origin 쌍별 정책은 아직 해결·검증 완료가 아니다.
- **G04 부분 해결:** 명시한 도메인 소유 쿠키를 하위 도메인·공유 Domain·HttpOnly·경로·분할 키까지 포함해 삭제한다. 지정한 origin 목록의 LocalStorage·IndexedDB·CacheStorage·service worker도 지우고 무관한 도메인과 유사 이름 도메인은 보존했다. 다른 소유 도메인의 CHIPS는 현재 삭제 범위에서 보존한다. 전체 저장 origin/storage key 탐색, 분할 저장소 전체, 기간·종류 선택, 열린 탭 재생성·부분 실패 복구는 별도 잔여 사항이다.

**판정:** 확인한 거절·초기화 및 명시 범위 삭제 경로는 통과. G04·G06 전체와 CEF 전체 채택은 보류 유지. 이번 소스는 검증 후보이며 G02 소스와 합친 제품 런타임 검증은 아니다.


## 9. G06 추가 검증 — 미통과

[추가 검증 기록](devlog/2026-11-11-g06-validation.md): G06 전용 probe의 최종 25개 검사 중 **19개 통과·6개 실패**. 정상 종료 1회, 종료 코드 0, 네트워크 서비스 재시작 0이다. 이전 79/79는 같은 origin의 명시적 거절과 당시 정의한 범위의 결과이며, 이번 임베디드 origin의 확장 검사를 포함하지 않았다.

- 사전 차단 설정이 없는 위치 요청은 이번 전용 번들의 전경 상태에서 native prompt callback에 도달했고, 오류 코드 1과 query denied가 일치했다. 메타데이터·활성화 조건이 이전 probe와 달라 기존 무응답의 단일 원인을 확정하지 않는다.
- 카메라·마이크 각각에서 (1) Permissions Policy로 금지한 iframe 요청까지 해당 origin의 단독 페이지 거절 설정으로 저장, (2) 위임한 iframe의 요청 거절 후 query가 prompt로 남음, (3) iframe 거절이 단독 페이지로 전파되는 문제가 재현됐다. 세 종류 × 두 권한 = 6개 실패다. 상위 페이지 A 자체의 설정은 prompt로 유지됐다.
- OS 상태 조회만 수행했다. Launch Services 실행은 로컬 서명 검사 통과 후에도 `Operation not permitted`로 실패했다. 직접 실행한 프로세스의 OS 상태는 독립 앱의 TCC 거부·복구 증거가 아니다. 실제 OS 승인/거부·복구, 장치 사용, 사용자용 복구 안내 검증은 미완료다.

**G06 미통과.** 요청 origin·최상위 origin·Permissions Policy를 구분하는 미디어 정책 저장 경로 수정이 필요하다. 실패 항목을 지원 범위에서 빼거나 query를 JavaScript로 덮어쓰지 않았다. CEF 전체 채택 보류를 유지하며, G02 확정과 G04 소스는 변경하지 않았다.


## 10. G06 OS 권한 수동 검증 후 상태

[수동 검증 기록](devlog/2026-11-11-g06-manual-validation.md): 사용자가 실제 macOS 권한 창과 설정을 조작했고, 독립 bundle ID의 앱에서 카메라·마이크·위치·알림의 **거부 상태 및 설정 변경 후 허용 복구**를 확인했다. 앞 절의 Launch Services 실행 차단은 새 수동 runner에서 해소됐다. 외부 stdout/stderr 리디렉션을 제거하고 실행 환경을 최소화했으므로 단일 원인은 확정하지 않는다.

카메라·마이크의 설정 변경 후 자동 재실행은 3회 실패했다고 사용자가 보고했고, 별도 실행으로 복구 상태를 확인했다. 위치·알림은 재시작 없이 상태 변경을 읽었다. 알림은 이미 거부된 상태에서 시작했으며 최초 거절 팝업 검증은 아니다.

**G06 전체는 여전히 미통과다.** OS 상태 전환 확인은 기존 iframe 6개 실패를 해결하지 않는다. 웹 요청·OS 권한 결합, 실제 장치 사용, 자동 재실행·제품 복구 안내는 남아 있다. 촬영·녹음·좌표 수집·알림 발송은 이번 단계에서 수행하지 않았다.


## 11. iframe 미디어 요청 거절 수정 — 2026-11-12

사용자는 iframe 카메라·마이크 요청의 정책을 **“이번 요청만 거절 — 다른 권한 유지”**로 선택했다. [수정·재검증 기록](devlog/2026-11-12-iframe-permission-fix.md)의 최종 정책 검사 25개와 경계 검사 22개, **47/47 통과**를 근거로 이 범위의 수정은 검증 완료다.

수정본은 iframe 요청에서 content setting을 저장하지 않고 해당 요청 callback만 취소한다. Permissions Policy에 의해 금지된 iframe, 위임된 iframe, 동일 출처·여러 sibling·다른 상위 사이트의 iframe 모두 단독 사이트 권한으로 거절을 전파하지 않는다. 기존에 저장된 거절도 지우지 않는다.

기존 6개 실패 중 상태 전파 4개는 코드 수정으로 해결했다. 나머지 2개는 요청 취소에도 영구 차단의 query denied를 요구했던 조건이다. 원래 실패 기록은 보존하고, 사용자가 선택한 요청 단위 거절에 맞춰 query prompt 유지로 수용 기준을 명시했다. 실제 미디어 요청은 NotAllowedError로 거절된다. JavaScript 권한 API를 덮어쓰지 않았다.

이 결과는 iframe별 독립 영구 차단이나 허용 기능을 확정한 것이 아니다. G06의 웹 요청·OS 권한 결합, 실제 장치 사용·복구 UX 및 자동 재실행 문제, G02와 합친 제품 런타임 검증은 남아 있으며 CEF 전체 채택 보류를 유지한다.


## 12. 알림 API 충돌·중복 등록 수정 — 2026-11-12
