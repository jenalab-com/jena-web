# CEF 배포 입력과 서명 후 패키지 식별

한 제품 빌드 디렉터리는 하나의 CEF 배포본에 귀속한다. 구성 시 include/libcef_dll/cmake/framework의 파일과 심볼릭 링크를 결정적인 순서로 SHA-256에 포함하고 lock을 만든다. 재구성 및 패키징에서 입력 불일치는 실패다. 같은 버전의 다른 GN 설정도 파일 내용이 다르면 새 빌드 디렉터리를 요구한다.

기존 앱이 있으면 앱 옆 영수증에 기록한 source identity와 서명 후 framework digest를 비교한다. 서명이 바이너리를 바꾸므로 source digest와 signed digest를 혼동하지 않는다. 영수증이 없는 기존 앱은 자동으로 신뢰하거나 교체하지 않는다. 코드 서명 후 영수증을 앱 밖에 기록한다.

대안인 version 문자열 비교는 같은 revision의 코덱 구성 차이를 놓치고, 매번 덮어쓰기는 기존 산출물을 보존하지 못하므로 선택하지 않았다. 파일 해시는 코덱 지원의 증거 또는 출처 서명 검증을 대신하지 않으며, 배포본 내부가 올바르게 제작됐는지는 공급 기록에 남긴다. 신규 제품 디렉터리로 연결해 기존 산출물과 프로필을 보존한다.
