# 데스크톱 탐색 앱 아키텍처 결정 기록

- 날짜: 2026-11-10
- 상태: 부분 대체됨. A01·A03은 후속 Swift 결정으로 대체, A02·A04는 제안 유지. 구현·PoC 미실행
- 결과: [기술 설계](../technical-design.md), [검증 계획](../design-validation.md)

## 맥락·가정

코드가 없는 초기 프로젝트이며 macOS 우선·Windows 후속, Blink 기반 탐색과 로컬 로그인 유지가 요구된다. 단일 로컬 사용자·다중 탭을 가정하며 원격 서비스 확장은 요구되지 않았다. 팀 규모·부하·성능 예산은 미확정이다.

## A01. 엔진과 UI — Superseded

사용자 요청으로 Electron·React 및 OS 공통화 우선 전제를 철회했다. 아래 내용은 과거 기록이며 [Swift 설계 결정](2026-11-10-swift-native-design.md)이 대체한다.

- 대안: Electron, Qt WebEngine, CEF.
- 제안: Electron + TypeScript + React를 첫 검증 후보로 삼는다.
- 이유: 웹 콘텐츠와 앱 UI를 분리하고 OS 간 공통 앱 로직을 둘 수 있다.
- 비용: 임의 사이트를 다루는 보안 책임, 메모리와 네이티브 통합, 서드 파티 쿠키 제어의 API 불확실성.
- 확정 조건: G01–G08, 특히 G04·G05 통과. 미충족이면 같은 기준으로 대안을 검증하며 PRD를 축소하지 않는다.

## A02. 로컬 데이터 소유권 — Proposed

- 대안: JSON 파일만 사용, 앱 SQLite, 서버 DB.
- 제안: 앱 설정·북마크·방문 기록·권한 정책은 SQLite, 웹 데이터는 엔진 프로필이 소유한다.
- 이유: 앱 데이터의 트랜잭션과 선택 삭제를 다루면서 엔진 DB의 내부 구조 의존을 피한다.
- 비용: 앱 DB와 엔진 작업의 원자성은 보장하지 못한다. 버전 마이그레이션·백업 정책이 필요하다.
- 예외 근거: 서버 무상태 지침은 이 로컬 데스크톱 제품에 적용하지 않는다. PRD의 로컬 보존 요구가 우선한다.

## A03. 신뢰 경계·기능별 모듈 — Superseded

웹 UI IPC 구성은 [Swift 설계 결정](2026-11-10-swift-native-design.md)으로 대체한다. 기능별 경계와 외부 페이지 권한 분리 원칙은 유지한다.

- 대안: 앱 UI와 외부 페이지에 동일 bridge 제공, 분리된 webContents와 최소 IPC.
- 제안: 외부 페이지에 앱 권한을 주지 않고 Main의 응용 서비스만 부수효과를 수행한다. 도메인은 프레임워크에서 분리한다.
- 이유: 임의 웹 콘텐츠가 파일·설정·삭제 명령을 실행할 수 없도록 한다.
- 비용: IPC 검증·뷰 배치·포커스 제어가 필요하다. 엔진 교체 시 adapter뿐 아니라 실제 호환성 재검증도 필요하다.

## A04. 삭제 계획과 부분 성공 — Proposed

- 대안: 직접 일괄 삭제, 확인 가능한 삭제 계획 후 실행.
- 제안: 실제 엔진 능력으로 범위를 산출하고 확인 후 항목별 실행·결과를 반환한다.
- 이유: 삭제 대상을 넘는 데이터 손실과 부분 실패 은폐를 방지한다.
- 비용: 동시 쓰기·worker·삭제 후 재생성 문제는 별도 검증해야 한다. 삭제 직전 자동 백업은 개인정보 삭제 의미와 충돌하므로 생성하지 않는다.

## 당시 유지한 유보 사항

PRD D01–D10의 제품 선택은 확정하지 않았다. 새 탭의 기본값, 제공처 목록, 비밀번호 별도 저장, 지원 OS, 배포 방식은 기존 합의 상태를 유지한다. 이번 작업은 설계 문서 추가이며 기존 원안·기획서·PRD를 변경하지 않는다.
