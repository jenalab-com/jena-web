# PRD 작성 결정 기록

- 날짜: 2026-11-10
- 요청: 기존 기획서에 따라 PRD 작성
- 근거: [제품 기획서](../product-plan.md)
- 결과: [PRD](../prd.md)

## 문제 맥락

기획서의 제품 방향을 개발·검증에서 추적할 수 있도록 요구사항, 수용 기준, 화면 상태와 출시 조건으로 구체화해야 한다.

## 검토한 방향과 선택

- 기존 기획서를 덮어쓰는 방식과 별도 PRD를 추가하는 방식을 비교했다. 원안·기획서를 보존하고 요구사항 추적을 제공하기 위해 별도 문서를 추가했다.
- 미확정 기본값을 임의로 정하는 방식과 결정 목록으로 관리하는 방식을 비교했다. 사용자 합의 범위를 유지하기 위해 D01–D10으로 남겼다.
- 기능 우선순위를 이유로 개인정보 설정을 후속 출시로 미루지 않았다. 기획서대로 macOS 첫 출시 필수 범위를 유지했다.

## 구체화와 근거

- F01–F13을 R01–R13으로 일대일 연결해 원안 대비 누락 여부를 확인할 수 있게 했다.
- 검색·이미지 페이지 내부 상호작용과 일반 링크 이동을 구분해 무조건 새 탭 처리로 폼·로그인이 깨지는 문제를 방지한다.
- 세션 보존과 비밀번호 저장을 분리했다. 자동입력은 범위 밖, 별도 저장은 유보 상태를 유지한다.
- 로컬 QA 지표를 정의하되 원격 사용자 추적을 새로운 기능으로 추가하지 않는다.
- 수용 기준의 100% 목표는 명시한 테스트 범위에 한정하고 전체 사이트 호환성으로 확대하지 않는다.

## 범위와 유보

기술 스택·제공처 목록·정책 기본값·배포 채널·개발 일정은 결정하지 않았다. 현재 작업은 문서 작성이며 코드 구현과 배포는 수행하지 않는다.

## 단계 확인

- 사용자 목적과 흐름: 기획서 및 대화에서 확인된 내용 유지.
- 화면·상태: 기능 수준으로 상세화, 시각 디자인 미진행.
- 요구사항·검증: 수용 기준과 출시 조건 작성.
- 준비 상태: 미확정 정책과 기술 검증을 명시해 구현 완료나 준비 완료로 오인하지 않도록 했다.
