# 웹 탐색 앱 기획 결정 기록

- 날짜: 2026-11-10
- 근거: `docs/concept.md`와 사용자 대화
- 결과 문서: [제품 기획서](../product-plan.md)

## 문제와 목표

검색·이미지 탐색에서 결과 목록과 방문 사이트를 앱 내부 탭으로 오가고, 재방문 때 유효한 로그인을 유지하려는 요구를 구체화한다.

## 검토한 선택지와 결정

| 주제 | 검토한 선택지 | 선택과 이유 | 범위 영향 |
|---|---|---|---|
| 플랫폼 | macOS / Windows 및 개발 순서 | 사용자 요청에 따라 macOS 우선, Windows 후속 | Windows 지원 목표 유지 |
| 검색 표시 | API로 자체 화면 구성 / 검색 사이트 페이지 표시 | 사용자가 검색 사이트 페이지 표시를 선택 | 검색 API 연동과 자체 결과 UI 불필요 |
| 검색 제공처 | Google 고정 / 사용자 선택 | 사용자가 검색엔진 선택을 요청 | 지원 목록·기본값은 추후 결정 |
| 이미지 검색 | Google API / 이미지 검색 페이지 표시 | API 없이 Google 이미지 결과 페이지 등을 여는 흐름에 최종 동의 | 웹·이미지 검색 모두 페이지 탐색 방식 |
| 사이트 방문 | 외부 브라우저 / 앱 내부 탐색 | 사용자가 앱 내부 탭 동작을 확인하고 동의 | 새 탭 설정 시 검색 결과 탭 보존 |
| 로그인 | 비밀번호 자동입력 / 인증 상태 보존 | 자동입력 불필요, 사이트별 유효기간 내 로그인 유지 요청 | 쿠키·사이트 데이터 보존 필요 |

## 보존과 유보 사항

- 원안은 수정하지 않고 별도 기획서를 추가한다.
- 원안의 비밀번호·키체인 저장은 후속 대화에서 삭제를 명시적으로 확정하지 않았다. 로그인 유지와 분리해 필요 여부를 유보한다.
- Blink 기반은 유지하되 CEF, Qt WebEngine 등 구체 스택은 결정하지 않는다.
- 검색 제공처 목록, 기본값, 탭 포커스, OS 지원 범위, 다운로드·외부 앱 링크, 배포 방식은 합의되지 않아 유보한다.
- 기획서의 수용 기준과 검증 목표는 합의 내용을 구현 가능한 수준으로 풀어 쓴 제안이며 검증 실적으로 취급하지 않는다.

## 단계별 확인

- 사용자 목적: 검색과 이미지 탐색, 탭 이동, 사이트별 로그인 유지 확인.
- 주요 흐름: 검색 사이트 페이지 → 결과 링크 → 앱 내부 탭 탐색 확인.
- 화면과 상태: 기획서에 기능 수준으로 정리. 시각 디자인은 미진행.
- 구현 준비: 미확정 정책과 기술 검증이 남아 있으며 개발·배포 일정은 미확정.
