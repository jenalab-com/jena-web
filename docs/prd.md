# Jena Web PRD

- 버전: 0.1
- 작성일: 2026-11-10
- 기준 문서: [제품 기획서](product-plan.md), [원안](concept.md)
- 상태: 요구사항 초안. 확정된 제품 방향을 상세화했으며, 미확정 정책은 §10에서 관리한다.
- 첫 출시 대상: macOS. Windows는 후속 출시 대상이며 지원 목표를 유지한다.
- 의사결정권자: 사용자. 개발 담당·출시 일정은 미정이다.

## 1. 문제와 제품 목표

검색과 이미지 탐색으로 자료를 찾는 사용자는 검색 결과를 보존하면서 여러 사이트를 비교하고, 저장한 사이트와 로그인한 사이트를 다시 방문하고 싶다. Jena Web은 검색 서비스가 제공하는 화면을 그대로 사용하면서 이 흐름을 앱 내부 탭에서 이어가게 한다.

**제품 약속:** 원하는 검색엔진으로 웹과 이미지를 검색하고, 결과 사이트를 앱의 탭에서 탐색하며, 사이트가 허용하는 동안 로그인 상태를 유지한다.

### 사용자와 핵심 과업

| 사용자 상황 | 원하는 행동 | 기대 결과 |
|---|---|---|
| 검색 결과에서 여러 참고 자료 비교 | 결과 링크를 새 탭으로 열기 | 원래 검색 결과를 잃지 않고 비교 |
| 이미지 참고 자료 조사 | 이미지 검색 후 미리보기·원본 사이트 탐색 | 익숙한 검색 서비스 화면에서 조사 지속 |
| 자주 사용하는 사이트 재방문 | 북마크 열기와 로그인 유지 | 주소 재검색·불필요한 재로그인 감소 |
| 특정 사이트의 데이터·권한 관리 | 대상과 영향을 확인하고 설정 변경·삭제 | 원하는 범위만 통제 |

별도 인터뷰나 시장 수요 검증은 수행하지 않았다. 본 PRD는 사용자가 대화에서 밝힌 개인 사용 요구를 근거로 한다.

## 2. 범위와 전제

### 2.1 첫 macOS 출시 필수 범위

검색엔진 선택, 웹·이미지 검색 페이지 표시, 주소 직접 이동, 탭과 기본 이동, 북마크, 사이트별 로그인 유지, 방문 기록·사이트 데이터·캐시 삭제, 사이트 권한, 서드 파티 쿠키와 팝업 제어를 포함한다. 아래 R01–R13은 모두 필수이며 개발 순서는 출시 범위 축소를 의미하지 않는다.

### 2.2 범위 밖과 유보 항목

- 범위 밖: 자체 검색 결과·이미지 갤러리, 검색 API 연동, 비밀번호 자동입력, 앱 고유 역이미지 검색 도구, 개발자 도구 중심 기능, 확장 프로그램 생태계, 기기 간 동기화, 모바일 버전.
- 후속 출시: Windows에서 동일한 사용자 결과 제공.
- 유보: 별도 비밀번호·키체인 저장, 다운로드, 외부 앱 링크, 탭 복원 등 §10의 항목. 유보는 삭제나 구현 제외를 승인한 뜻이 아니다.
- 사이트 자체가 제공하는 이미지 업로드 검색 등을 막는 요구는 없다. 앱 전용 기능을 추가하지 않는다는 범위 정의다.

### 2.3 전제와 의존성

- Blink 기반 웹 실행 환경을 사용한다. 구체적인 엔진 임베딩·UI 프레임워크는 본 PRD에서 선정하지 않는다.
- 검색은 제공처의 결과 페이지로 이동하는 방식이다. Google 검색 API 키와 결과 데이터 수집 API는 요구하지 않는다.
- 일반 탐색에서 같은 프로필을 사용해 탭과 앱 재실행 간 데이터를 유지한다고 가정한다. 사용자용 다중 프로필 기능은 요구하지 않는다.
- 로그인 지속 여부는 사이트의 쿠키·토큰·서버 정책에 의존한다. 세션 만료·취소를 우회하거나 유효기간을 연장하지 않는다.
- 검색 사이트의 페이지 구조·탐색 방식 및 외부 인증 정책이 바뀔 수 있다. 지원 목록과 호환성 검증이 필요하다.

## 3. 성공 지표

수치는 출시 검증 목표이며 현재 실적이 아니다. 분모는 출시 전에 명시한 지원 검색엔진·대상 사이트·OS 조합의 테스트 사례 수다. 전체 웹사이트 호환성으로 해석하지 않는다.

| 지표 | 목표 | 측정 |
|---|---|---|
| 검색부터 사이트 방문까지 완료 | 필수 시나리오 100% 통과 | 웹·이미지 각각 실제 제공처에서 수행 |
| 새 탭 탐색 시 결과 보존 | 해당 시나리오 100% 통과 | 원본 탭 URL·내용과 대상 탭 확인 |
| 의도치 않은 외부 브라우저 실행 | 0건 | 일반 HTTP/HTTPS 탐색 관찰 |
| 유효한 영속 로그인 재사용 | 대상 시나리오 100% 통과 | 다른 탭·정상 종료 후 재실행 |
| 무효 인증의 잘못된 복원 | 0건 | 로그아웃·만료·사이트 데이터 삭제 후 재접속 |
| 데이터 삭제의 범위 준수 | 해당 시나리오 100% 통과 | 선택 데이터 제거·비선택 데이터 보존 비교 |
| 설정·북마크 보존 | 해당 시나리오 100% 통과 | 저장 후 정상 재실행 |

출시 이후 사용성 지표는 별도로 합의한다. 위 목표를 이유로 원격 사용자 추적을 도입하지 않는다.

## 4. 사용자 흐름

### U01. 웹 검색과 비교 탐색

검색엔진 설정 → 탐색 화면에서 웹 선택 → 검색어 입력 → 앱 탭에 검색 결과 표시 → 결과 링크 선택 → 탭 열기 정책 적용 → 사이트 탐색 → 결과 탭 복귀 또는 뒤로 가기.

### U02. 이미지 참고 자료 탐색

이미지 모드 선택 → 검색어 입력 → 검색 서비스의 이미지 결과 표시 → 서비스 내부 미리보기 → 원본 사이트 링크 선택 → 앱 탭에서 사이트 탐색.

썸네일 클릭·페이지 내 미리보기와 원본 사이트 이동은 구분한다. 서비스 내부 미리보기를 임의로 새 탭 이동으로 바꾸지 않는다.

### U03. 로그인한 사이트 재방문

사이트에서 직접 로그인 → 쿠키·사이트 데이터 보존 → 다른 탭 또는 재실행 후 재방문 → 유효하면 로그인 상태 사용 / 만료·취소되었으면 사이트의 재인증 화면 표시.

### U04. 개인정보 삭제

개인정보 설정 → 데이터 종류·범위 선택 → 영향 검토 → 삭제 확인 → 처리 중 상태 → 완료 또는 항목별 실패 안내 → 실패 항목 재시도.

## 5. 기능 요구사항

각 수용 기준은 정상 동작뿐 아니라 사용자의 탐색 목적이 유지되는지 확인한다. R 번호는 제품 기획서의 F 번호와 일대일 대응한다.

### R01. 검색엔진 선택 — F01

- 사용자는 지원 검색엔진 목록에서 제공처를 선택할 수 있다. Google을 포함하되 추가 제공처·초기 기본값은 D01에서 확정한다.
- **AC01:** 제공처 A를 선택한 후 검색하면 A의 결과 페이지가 앱에 열린다. 선택을 바꾸지 않고 재실행해도 A를 사용하여 반복 설정을 줄인다.
- **AC02:** 저장 실패 시 성공으로 표시하지 않고 기존 유효 설정과 사용자의 선택을 구분해 재시도할 수 있다.
- **AC03:** 이미지 미지원 제공처는 이유를 표시한다. 사용자에게 알리지 않고 다른 제공처로 검색어를 보내지 않는다.

### R02. 웹 검색 — F02

- **AC01:** 웹 모드에서 검색하면 한글·공백·특수문자를 보존한 검색어가 선택한 제공처에 전달되고 결과 페이지가 앱 탭에 표시된다.
- **AC02:** 빈 입력·공백만 입력한 경우 검색 요청을 만들지 않는다. 한글 조합 확정 입력과 검색 제출이 충돌해 중복 탐색을 만들지 않아야 한다.
- **AC03:** 네트워크 오류 시 입력을 보존하고 재시도를 제공한다. 검색 결과가 없는 경우는 제공처의 결과 없음 화면을 사용한다.

### R03. 이미지 검색 — F03

- **AC01:** 이미지 모드로 검색하면 선택 정책에 맞는 제공처의 이미지 결과 페이지를 표시한다. 자체 갤러리로 변환하거나 검색 결과 API를 호출하지 않는다.
- **AC02:** 이미지 미리보기를 연 뒤 원본 사이트로 이동할 수 있다. 앱의 탭 정책이 미리보기·페이지 내부 상호작용을 깨뜨리지 않아야 한다.
- **AC03:** 제공처가 이미지 검색을 지원하지 않으면 검색 실행 전에 대체 선택 경로를 제공하고 검색어를 유지한다.

### R04. 주소 직접 이동 — F04

- **AC01:** 명시적인 유효 HTTP/HTTPS 주소 입력은 검색엔진을 거치지 않고 해당 주소로 이동하여 목적 사이트에 직접 접근한다.
- **AC02:** 리디렉션 후 주소 표시를 최종 접속 위치에 맞춰 갱신한다. 웹페이지가 앱의 주소 표시를 임의로 위조할 수 없어야 한다.
- **AC03:** 잘못된 주소·지원하지 않는 스킴을 입력하면 오류나 처리 안내를 제공하며 입력을 보존한다. 상세 판별 규칙은 D04에서 확정한다.

### R05. 탭 탐색 — F05

- 탭 생성·선택·닫기를 제공하고 각 탭의 제목과 로딩 상태를 구분한다.
- **AC01:** 새 탭 열기로 설정한 상태에서 적용 대상 결과 링크를 누르면 원래 결과 탭을 유지하고 목적 페이지를 앱 내부 탭 하나에 연다.
- **AC02:** 현재 탭 열기로 설정한 상태에서는 적용 대상 링크가 현재 탭에서 이동하고 뒤로 가기로 검색 결과에 복귀할 수 있다.
- **AC03:** 탭을 전환해도 다른 탭의 탐색 상태를 임의로 초기화하지 않는다. 일반 HTTP/HTTPS 링크로 외부 Chrome·Safari가 실행되지 않는다.
- **AC04:** 페이지 내부 앵커·이미지 미리보기·폼 제출은 무조건 새 탭으로 전환하지 않는다. 스크립트 새 창과 인증 팝업은 R13 및 D05와 함께 검증한다.
- 링크 유형별 정책 적용 범위, 포커스·마지막 탭·복원 정책은 D03에서 확정한다.

### R06. 기본 이동 — F06

- **AC01:** 뒤로·앞으로·새로고침이 활성 탭에만 적용된다. 이동 기록이 없을 때 해당 이동을 비활성으로 표시한다.
- **AC02:** 탭 전환 시 주소 표시가 선택 탭과 일치한다. 로딩 실패 후에도 주소 수정과 재시도를 사용할 수 있다.

### R07. 북마크 — F07

- **AC01:** 현재 페이지의 제목·주소를 저장하고 목록에서 다시 열 수 있다. 정상 재실행 후에도 동일 항목을 사용할 수 있다.
- **AC02:** 제목·주소 편집을 저장하면 변경 사항이 반영된다. 삭제는 대상을 확인한 후 수행하며 취소 시 보존한다.
- **AC03:** 저장·편집·삭제 실패 시 성공으로 표시하지 않고 재시도를 제공한다. 빈 목록에는 북마크 추가 경로를 안내한다.
- 폴더·태그·가져오기·내보내기는 본 요구사항에서 추가하지 않는다.

### R08. 사이트별 로그인 유지 — F08

- **AC01:** 영속 로그인을 허용하는 사이트 A에 직접 로그인한 후 새 탭과 정상 재실행에서 유효한 인증 상태를 재사용한다.
- **AC02:** A와 B에 각각 로그인해도 사이트 경계를 넘어 인증 정보를 앱이 임의로 전달하지 않는다. 정상적인 사이트 간 인증 리디렉션은 해당 프로토콜을 따른다.
- **AC03:** 로그아웃·서버 세션 취소·만료 후에는 사이트가 요구하는 인증을 따른다. 오래된 저장 상태로 인증을 복원하지 않는다.
- **AC04:** 종료 시 만료되는 세션과 영속 세션을 구분한다. 사이트 정책에 반해 모든 세션을 강제로 영구 보존하지 않는다.
- 비밀번호 자동입력을 구현하지 않는다. 별도 비밀번호 저장은 D07에서 결정한다.

### R09. 인터넷 사용 기록 삭제 — F09

- 방문 기록, 쿠키·사이트 데이터, 캐시를 분리해 선택하도록 한다.
- **AC01:** 방문 기록만 삭제하면 선택 범위의 기록이 제거되고 비선택 쿠키·북마크가 유지되어 불필요한 로그아웃과 원본 손실을 피한다.
- **AC02:** 쿠키·사이트 데이터 삭제 전 로그인 해제 가능성과 대상 범위를 표시한다. 취소하면 데이터를 변경하지 않는다.
- **AC03:** 캐시만 삭제했을 때 인증 데이터까지 삭제하지 않는다. 항목 일부 삭제 실패는 부분 성공으로 표시하고 실제 완료 범위를 알린다.
- 지원 기간·범위와 사이트 데이터 유형은 D06에서 확정하며 지원하지 않는 범위를 UI에서 약속하지 않는다.

### R10. 사이트별 데이터 삭제 — F10

- **AC01:** 사이트 A의 대상 데이터를 삭제하면 재방문 시 해당 데이터가 없어야 한다. 무관한 사이트 B의 데이터·로그인·북마크는 보존한다.
- **AC02:** 하위 도메인·공유 인증 도메인·분할 저장소 등 실제 삭제 경계를 확인하고 표시한다. 연동 사이트에 대한 파급효과를 무조건 없다고 보장하지 않는다.
- **AC03:** 열린 탭이 데이터를 다시 생성하는 경우를 검증하고, 삭제 완료와 이후 재생성을 구분한다. 사용자 탭을 임의로 닫는 방식으로 처리하지 않는다.

### R11. 사이트 권한 — F11

- **AC01:** 지원 권한에 대해 요청 사이트와 현재 상태를 표시하고 사이트별 허용·차단을 변경할 수 있다.
- **AC02:** 앱에서 허용해도 OS가 거부한 경우 OS 제한을 설명한다. 사용자가 복구할 수 있도록 필요한 설정 경로를 안내한다.
- **AC03:** 한 사이트의 변경으로 다른 사이트의 설정을 바꾸지 않는다. 변경 적용에 새로고침이 필요한 경우 알린다.
- 위치·카메라·마이크·알림 등 지원 목록과 초기 정책은 D08에서 엔진 검증 후 확정한다.

### R12. 서드 파티 쿠키 제어 — F12

- **AC01:** 선택한 쿠키 정책이 실제 웹 요청·저장에 적용되는지 검증한다. 설정 표시만 바뀌는 것으로 완료 처리하지 않는다.
- **AC02:** 차단으로 로그인 또는 콘텐츠가 동작하지 않을 때 사용자가 설정을 확인·변경할 수 있다. 사이트 동작 실패만으로 앱이 정책을 자동 완화하지 않는다.
- 기본값·사이트 예외·기존 쿠키에 대한 적용 시점은 D08에서 확정한다.

### R13. 팝업 제어 — F13

- **AC01:** 허용·차단 및 사이트별 정책을 제공한다. 차단 시 요청 사이트와 차단 사실을 알리고 설정 경로를 제공한다.
- **AC02:** 명시적인 새 탭 열기 동작과 자동 팝업을 구분한다. 차단된 자동 팝업을 외부 브라우저로 우회 실행하지 않는다.
- **AC03:** 인증 팝업이 허용된 경우 인증 완료 후 원래 페이지로 이어지는지 검증한다. 미지원 인증 흐름은 실패 원인을 안내하고 완료한 것처럼 표시하지 않는다.

사용자 데이터 보존 방식·파일 구조·DB는 기술 설계에서 정한다. OS별 보안 저장소 사용 여부는 엔진과 위협 검토를 거쳐 정하며 인증 데이터를 일반 로그에 남기지 않는다.

### 비기능 수용 기준

- **N01 보안:** 웹 콘텐츠가 앱의 파일·시스템 기능을 임의로 호출하지 못해야 한다. 엔진 격리와 샌드박스를 유지하며 인증서 오류를 자동 우회하지 않는다.
- **N02 개인정보:** 검색어·방문 URL·쿠키·토큰·비밀번호를 원격 분석 데이터로 전송하지 않는다. 검색 제공처에 검색어가 전달되는 정상 탐색과 앱의 원격 추적을 구분한다.
- **N03 접근성:** 검색, 탭 이동, 북마크와 설정을 키보드로 완료할 수 있고 포커스와 접근 가능한 이름을 제공한다. macOS 보조 기술로 앱 자체 주요 컨트롤을 검증한다.
- **N04 안정성:** 저장·삭제 실패를 성공으로 표시하지 않는다. 초기화나 데이터 제거를 자동 복구 수단으로 사용하지 않는다. 프로필 업그레이드가 필요하면 원본 보존과 복구 가능성을 검증한다.
- **N05 성능:** 기준 기기에서 실행 시간, 탭 전환 지연, 다중 탭 메모리를 측정한다. 외부 서버 지연과 앱 자체 지연을 구분한다. 수치 예산은 D09에서 확정 전까지 미검증으로 표기한다.
- **N06 업데이트:** 엔진 보안 업데이트 반영 경로와 배포 절차를 출시 전에 마련한다. 업데이트·복구 절차는 사용자 프로필 손실을 일으키지 않아야 한다.
- **N07 호환성:** 후속 Windows 릴리스도 같은 R01–R13 수용 기준을 적용한다. OS별 권한·저장·배포 동작은 별도로 검증한다.

## 8. 검증·관찰 계획

### 테스트 구성

1. 통제 가능한 테스트 사이트에서 영속 쿠키, 종료 시 만료 세션, 서버 취소, 팝업, 권한, 사이트 데이터 삭제를 재현한다.
2. 확정된 실제 검색 제공처에서 웹·이미지 검색과 미리보기·결과 이동을 검증한다.
3. 선정한 실제 로그인 사이트에서 직접 로그인, 외부 인증 리디렉션, 인증 팝업, 재실행 후 재방문을 확인한다.
4. 오프라인·저장 실패·삭제 부분 실패·인증서 오류를 포함해 복구 경로를 검증한다.

실제 사이트 계정 비밀번호나 토큰은 테스트 결과 문서에 기록하지 않는다. 외부 서비스 장애와 제품 결함은 구분하되, 검증하지 못한 사례는 통과 처리하지 않는다.

### 로컬 QA 관찰 항목

| 관찰 항목 | 필요한 값 | 기록하지 않는 값 |
|---|---|---|
| 검색 실행 | 모드, 제공처 식별자, 성공·실패 | 실제 검색어 |
| 탭 탐색 | 현재/새 탭 정책, 내부 처리 여부 | 방문 URL·페이지 내용 |
| 북마크·설정 저장 | 작업 종류, 성공·실패 | 북마크 제목·주소 |
| 데이터 삭제 | 테스트 대상 식별자, 데이터 종류, 완료·실패 | 쿠키·토큰·실제 계정 정보 |
| 로그인 유지 | 테스트 사례 ID, 기대 상태와 결과 | 비밀번호·세션 값 |

이는 테스트 관찰 규격이다. 별도 분석 서버나 사용자 행동 추적 기능을 추가하는 요구가 아니다.

문제 발생 시 배포 중단·수정 배포와 사용자 데이터 보존을 우선하는 복구 절차를 마련한다. 엔진 버전 변경으로 프로필 호환성이 깨질 수 있으므로 이전 버전 실행을 무조건 안전한 롤백으로 가정하지 않는다. 이 문서는 실제 배포·종료·데이터 변경을 실행하는 승인이 아니다.
